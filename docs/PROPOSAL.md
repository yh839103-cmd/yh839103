# LINE AI 聊天助理 計畫書

| 項目 | 內容 |
|---|---|
| 專案名稱 | LINE AI 聊天助理（line-ai-bot） |
| 版本 | v1.0 |
| 日期 | 2026-10-05 |
| 技術 | Python 3.12 · Flask · LINE Messaging API（line-bot-sdk v3）· Anthropic Claude API |

---

## 1. 專案背景與動機

LINE 是台灣最普及的通訊軟體，多數人每天都會打開。把 AI 助理直接放進 LINE，使用者不必另外下載 App 或登入網站，就能隨時用熟悉的聊天介面提問、查資料、整理想法。

## 2. 專案目標

1. 建立一個可在 LINE 一對一聊天與群組中使用的 AI 聊天機器人。
2. 支援多輪對話：機器人記得近期上下文，回答前後連貫。
3. 提供簡單指令（說明、清除記憶），讓使用者能掌控對話。
4. 程式碼結構清楚、有自動化測試，並公開於 GitHub，方便他人部署與延伸。

## 3. 功能需求

| 編號 | 功能 | 說明 | 優先度 |
|---|---|---|---|
| F1 | AI 對話 | 收到文字訊息後呼叫 Claude API 產生回覆 | 必要 |
| F2 | 對話記憶 | 每位使用者 / 每個群組保留最近 10 輪對話，閒置 1 小時自動清除 | 必要 |
| F3 | 指令 | `/help` 顯示說明、`/reset` 清除記憶（也支援中文「說明」「重新開始」） | 必要 |
| F4 | 歡迎訊息 | 使用者加好友時自動傳送說明 | 必要 |
| F5 | 長訊息切段 | 超過 LINE 5000 字上限時自動切段，最多 5 則 | 必要 |
| F6 | 讀取動畫 | AI 思考時顯示「輸入中」動畫 | 加分 |
| F7 | 錯誤處理 | AI 服務異常時回覆友善訊息，不留下錯誤紀錄 | 必要 |

### 非功能需求

- **安全性**：驗證 LINE `X-Line-Signature` 簽章，拒絕偽造請求；所有金鑰以環境變數管理，不進版控。
- **回應速度**：Webhook 立即回應 200，AI 處理於背景執行，避免 LINE 平台逾時重送。
- **可維護性**：核心邏輯與 SDK 解耦，可獨立單元測試；GitHub Actions 自動跑測試。

## 4. 系統架構

```
使用者 (LINE App)
      │ 傳送訊息
      ▼
LINE Platform ──Webhook (POST /callback)──▶ Flask 伺服器
                                              │ 1. 驗證簽章
                                              │ 2. 背景執行緒處理
                                              ▼
                                         ChatService
                                     ┌────────┴────────┐
                              ConversationStore     ClaudeLLM
                               (對話記憶)        (Anthropic API)
                                              │
LINE Platform ◀──Reply API──────────────────── 回覆訊息
```

### 程式模組

| 檔案 | 職責 |
|---|---|
| `app/main.py` | Flask 伺服器、Webhook 路由、LINE 事件處理 |
| `app/core.py` | 對話記憶、指令解析、訊息切段、對話流程（不依賴外部套件） |
| `app/llm.py` | 呼叫 Claude API，設定模型與系統提示詞 |
| `tests/test_core.py` | 核心邏輯單元測試 |

## 6. 部署方式

- **開發測試**：本機執行 + ngrok 產生 HTTPS 網址，填入 LINE Webhook URL。
- **正式上線**：Render（附 `render.yaml`）或任何支援 Docker 的平台（附 `Dockerfile`）。
- 伺服器以 gunicorn 單一 worker、多執行緒執行（對話記憶存在記憶體中，需單一行程）。

## 8. 風險與對策

| 風險 | 對策 |
|---|---|
| API 金鑰外洩 | 使用環境變數、`.gitignore` 排除 `.env`、外洩時立即撤銷重發 |
| AI 費用失控 | 限制單次回覆長度（max_tokens）、限制記憶輪數、設定帳單上限 |
| 伺服器重啟遺失對話記憶 | v1 可接受；v2 改用 Redis 儲存 |
| 群組內每則訊息都回覆太吵 | v2 加入「被提及（@）才回覆」模式 |
| AI 回答錯誤資訊 | 在說明中提醒使用者 AI 可能出錯，重要資訊請自行查證 |
